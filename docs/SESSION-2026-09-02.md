# Skema, session of 2 September 2026

What this app is, what got built, and what is still wrong. Written at the end
of a long session so the next one does not start from nothing.

## The app

`com.marcusrosado.skemafordtu`, version 0.4.0. A Kotlin Multiplatform calendar
that reads the DTU Learn ICS feed and shows it properly, built for a Pixel 10
Pro Fold. Private repo at github.com/marcusbandit/skema, `main` at 72f5c4e.

Month, week, day and agenda views. Week is the default because it is how a
timetable is read. Sidebar navigation, per semester colours, a gesture driven
detail sheet, and a semester screen that lists each term's subjects and its
typical week.

## The four data findings that mattered

Everything interesting came from reading the real feed rather than from the
spec.

1. **The course is only in LOCATION.** Every UID begins "6606-", the org unit,
   so the UID says nothing about which course an entry belongs to.
2. **DTU writes the term into LOCATION too**, and the display code was throwing
   it away as repetition. 694 of 712 entries carry one. That is where semesters
   come from.
3. **Duplicates must agree about length, not just start time.** 88 slots share
   a start and a course; 34 disagree about duration and 29 hold a zero length
   marker. Merging those took the marker's title and its empty end, which the
   grid clamps to midnight: a four hour class became an eleven hour block
   called "m02-solutions - Available".
4. **278 of 688 descriptions are one repeated TimeEdit paragraph**, identical
   but for a number, with no other text anywhere. It is a reservation number
   wearing a paragraph, and it is now a stamp.

## Bugs that only testing found

- Pinch zoom felt stuck because it wrote settings.json on every pointer event,
  on the main thread.
- Session restore silently did nothing: parsing 712 events outlasted the 600ms
  save debounce, so the position saver overwrote the session before restore
  read it.
- The detail sheet stuck part way because the nested scroll only settled when
  the fling velocity had the right sign, so a slow drag settled nothing.
- The day view opened on an empty 02:00 because it aimed at the clock rather
  than at the next thing that had not finished.
- The week view sized five day columns for the whole window and drew them into
  a pane two thirds that wide, so Friday fell off the edge.
- One course landed on hue 30 against DTU red's 29, so an ordinary lecture wore
  the clash marker.

## Still open

See `docs/FEEDBACK.md`, which is the live list. The big ones:

- **Animation smoothness is unverified.** The emulator renders in software, so
  its frame timings are meaningless, and `screenrecord` is broken on this AVD.
  Fluidity has to be judged on the real phone.
- The month and year picker needs a pass.
- The typical week inside a semester has been reworked twice and looked at
  once. Check it against the predicted table in the session log.
- Late January counts as a late autumn week rather than spring week 1. DTU runs
  a separate three week January period and which side owns it is unresolved.
- Unfolded, the calendar pane is about 415dp once the rail and the detail pane
  take their share. Levers are `RAIL_WIDTH` and the detail rail's 0.32 share.
- Background refresh while the app is closed, and a notification when something
  moves. `SkemaRepository.refresh` already returns a diff.

## Working notes

- Emulator is `skema_fold10`, a Pixel 10 Pro Fold profile. Measured off the
  device: 443 x 970 dp folded, 852 x 883 unfolded, so unfolding buys width and
  costs height. Headless, driven over adb.
- `scripts/`: emulator, build, run, shot, fold, postures, motion.
- The feed URL is a bearer credential. It is in the app's private storage, never
  in the repo, and it is rendered in plaintext on the Settings screen, so
  screenshots of that screen leak it.
- Every build handed over bumps `versionCode` and `versionName` first.
